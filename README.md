## אחסון ודיפלוי (Railway)

לדשבורד שני סוגי נתונים, והם מתנהגים אחרת:

| סוג | איפה | שורד דיפלוי? |
|-----|------|---------------|
| פרסונות מסודרות, דוגמאות, תוצרים | `DATA_PATH`, מגיע מ-git | כן, git הוא מקור האמת |
| תשובות מועמדים, פרסונות שנוצרו באפליקציה | `PERSISTENT_DATA_PATH`, Volume | רק אם ה-Volume מחובר |

Railway מוחק את מערכת הקבצים בכל דיפלוי, כולל דיפלוי שנובע משינוי קוד לא קשור.
לכן כל נתון שנכתב בזמן ריצה ואין לו מקור אמת אחר חייב לשבת על Volume.

**הקמה חד פעמית:**

1. Railway ← Service ← Volumes ← Volume חדש עם mount path `/data`
2. Railway ← Service ← Variables ← `PERSISTENT_DATA_PATH=/data`

**אימות** (אחרי כל שינוי בתשתית):

```bash
curl -s -b "dashboard_auth=<הסיסמה>" https://<domain>/api/health/storage
```

מצופה `{"ok":true,"level":"volume",...}`. כל תשובה אחרת אומרת שהגשות של מועמדים
בסכנה, ובמצב הזה טופס `/onboarding` נחסם אוטומטית ומוצג באנר אדום בדשבורד.

`railway.json` לא מגדיר Volumes ולא יכול להעיד עליהם, ההגדרה היא בממשק בלבד.
